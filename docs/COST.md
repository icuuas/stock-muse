# 费用（token）说明

**结论先说**：脚本本身是在云电脑里运行的普通程序，取数、算盈亏、判断规则**都不调用模型**。可能消耗额度的只有两处：
1. **定时任务每次唤醒 Muse**：这取决于 Muse 的定时任务怎么实现和计费，**本项目没有实测，不能下结论**。
2. **有内容要发时，Muse 排版并发送**：每条消息一次很短的生成。

## 额度大概花在哪里
| 环节 | 是否调用模型 | 说明 |
|---|---|---|
| 取行情、算盈亏、判断异动、过滤新闻 | 否 | 纯脚本 |
| 定时任务触发 | **未知** | 如果每次触发都启动一轮 Agent 对话，空跑也会消耗；取决于平台 |
| 没事时（输出 `NOOP`） | 取决于上一行 | 任务指令已压到最短：“运行一条命令，第一行是 NOOP 就立即结束，不要回复” |
| 有提醒、日报、消息时 | 是 | Muse 读 `draft`、按渠道排版、发送；信息推送还会补一句话概括 |
| 用户随时问“我的持仓” | 是 | 一次普通对话 |
| Space 看板刷新 | 取决于实现 | 默认 10 分钟推送一次，只在开盘时段 |

## 本项目已经做的节省
- **只在开盘时段建任务**，不是 24 小时空转；A 股和港股共用一个任务。
- **只为有持仓的市场建任务**；美股夜盘任务只有自测通过才创建。
- **提醒速度三档**：实时（1 分钟）、均衡（5 分钟，默认）、省额度（15 分钟）。
- 没事就输出 `NOOP`，指令要求“不回复、立即结束”。
- 看板默认 10 分钟才更新一次；新闻检查和日报也有频率限制。

## 每个交易日大概唤醒多少次
只是算术（详见 `cron/CRON.md`），不是 token 数：

| 全部持有（A 股+港股、美股、夜盘） | 唤醒次数 |
|---|---|
| 实时 | 约 1,540 |
| 均衡（默认） | 约 320 |
| 省额度 | 约 110 |

只持有一个市场会少很多。另外每个交易日最多还有 4 个日报任务。

## 还不知道的事（请 Muse 实测）
把下面这段发给 Muse，把结果贴回来：

```
请实测并如实回答（测不了写"无法测试"）：
1. 一个定时任务（cron）每次触发时，是否会启动一轮完整的 Agent 对话并消耗模型额度？还是可以只执行命令、不调用模型？
2. 如果每次触发都消耗额度：任务内容只有"运行一条命令，输出第一行是 NOOP 就立即结束，不要回复"，一次这样的空跑大约消耗多少？请建一个每 5 分钟的测试任务跑 30 分钟，对比前后的额度或用量，汇报结果后删除测试任务。
3. 有没有"只执行脚本、仅当脚本有输出时才唤醒 Agent"的任务类型或设置？
4. Space 的 action 能否由 cron 直接调用（不经过 Agent）？如果能，Space 的服务端代码能否自己取数，这样看板刷新就不需要唤醒 Muse？
5. 免费版和付费版对后台定时任务有没有次数或额度的限制？达到上限时任务会怎样？
```

## 如果实测发现空跑也耗额度
- 优先改成“省额度”档，或让用户只保留日报、不开实时异动。
- 如果平台有“脚本有输出才唤醒”的任务类型，把监测任务改成那种，成本会降到只有发消息的部分。
- 如果 Space 的 action 能由 cron 直接调用，并且服务端能自己取数，可以让看板刷新完全不走 Muse。
